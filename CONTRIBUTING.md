# Contributing

Thanks for your interest in contributing. Please read the project README and any project-specific documentation before making changes.

## Before opening a pull request

1. Check existing issues and pull requests to avoid duplicating work.
2. For substantial changes, open an issue first to discuss the intended behavior and scope.
3. Create a focused branch from the default branch.
4. Keep changes small and related to one purpose.
5. Update documentation when setup, behavior, configuration, or limitations change.
6. Add or update tests where the project has a relevant test suite.
7. Run the checks documented in the README or project configuration, and report exactly what you ran. Do not claim checks passed if they were not run.

## Pull request expectations

Explain what changed and why, any user-visible behavior or compatibility impact, how the change was tested (including commands and results), and known limitations or migration steps.

Do not include secrets, private user data, generated build output, local databases, virtual environments, or machine-specific configuration. Do not add third-party assets or datasets unless their source and redistribution terms are documented.

## Code and documentation quality

Prefer readable, maintainable changes over unnecessary abstraction. Preserve existing project conventions. Avoid unrelated formatting changes, unexplained dependency additions, and claims that exceed the available test evidence.

## Licensing

By submitting a contribution, you confirm that you have the right to submit it under the repository's stated license. Keep third-party code, media, fonts, datasets, and other separately licensed materials clearly identified; do not relicense them as part of this project.
